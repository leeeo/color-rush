# 06. 안드로이드 출시

> 문서 목적: 서명 키를 만들고, 릴리즈 AAB를 빌드하고, Play Console에서 실제로 Color Rush를 심사에 제출해 프로덕션에 출시합니다.

## ✅ 선행 조건

- [ ] **[04-AdMob-설정.md](./04-AdMob-설정.md)**: 광고 ID를 실제 값으로 교체 완료 (교체 안 하면 테스트 광고만 나오는 상태로 출시됩니다. 출시 자체는 가능하지만 수익이 0원입니다.)
- [ ] **[05-인앱결제-설정.md](./05-인앱결제-설정.md)**: `remove_ads` 상품 등록 완료 (또는 최소한 Google Play 판매자 계정 준비)
- [ ] **08번 문서(웹사이트 배포)**: 개인정보처리방침 페이지가 실제 URL로 접근 가능해야 합니다 (`https://아이디.github.io/저장소명/privacy.html` 형태). 이 문서 5장의 데이터 보안 양식과 6장의 스토어 등록정보에서 이 URL이 필요합니다. 08번 문서 담당자가 먼저 배포를 끝내야 합니다.
- [ ] Windows 11 + PowerShell 환경, `scripts\setup-android.ps1`로 JDK 17 + Android SDK 설치 완료
- [ ] 신용카드 또는 결제 가능한 카드 (Play 개발자 등록비 $25, 1회성)

## ⏱ 예상 소요 시간

- 실작업: 2~4시간 (키 생성, 빌드, 계정 만들기, 스토어 등록정보 작성 전부 포함)
- 대기 시간(별도): 개발자 계정 신원 확인 수 시간~2일, 내부 테스트 반영 수 시간, **신규 개인 계정은 비공개 테스트 14일 유지 필요할 수 있음(아래 7장 참고)**, 프로덕션 심사 수시간~7일

## 1. 업로드 키스토어 생성

이 키는 Color Rush 앱을 서명하는 데 쓰이며, **앱을 처음 낸 이후로 계속 같은 키로 업데이트**해야 합니다.

### 1-1. keytool 실행

`scripts\setup-android.ps1`이 설치한 JDK 17(Temurin)의 `keytool.exe`를 사용합니다. 보통 경로는 다음과 같습니다.

```
C:\Users\<사용자명>\scoop\apps\temurin17-jdk\current\bin\keytool.exe
```

새 터미널을 열었다면 `JAVA_HOME`이 자동으로 잡혀 있어 `keytool` 명령을 바로 쓸 수 있습니다. PATH가 아직 안 잡혔거나 "keytool을 찾을 수 없습니다" 오류가 나면, 전체 경로로 직접 실행하세요.

```powershell
& "C:\Users\$env:USERNAME\scoop\apps\temurin17-jdk\current\bin\keytool.exe" -genkey -v `
  -keystore D:\Projects\leeeo-colorrush\app\android\upload-keystore.jks `
  -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

PATH가 정상적으로 잡혀 있다면 아래처럼 짧게 실행해도 됩니다.

```powershell
keytool -genkey -v -keystore D:\Projects\leeeo-colorrush\app\android\upload-keystore.jks -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

### 1-2. 질문 항목 답변 예시

명령을 실행하면 아래와 같은 질문이 순서대로 나옵니다. 이름/조직 정보는 스토어에 노출되지 않으니 편하게 채우면 됩니다.

| 질문 | 답변 예시 |
| --- | --- |
| 키스토어 비밀번호 입력 | (직접 정한 안전한 비밀번호, 잊지 않도록 기록) |
| 새 비밀번호 다시 입력 | (위와 동일하게 한 번 더) |
| 이름과 성을 입력하십시오 | 본인 이름 또는 팀/서비스 이름 |
| 조직 단위 이름을 입력하십시오 | Color Rush (또는 그냥 Enter로 생략) |
| 조직 이름을 입력하십시오 | 개인 개발자면 본인 이름, 사업자면 상호명 |
| 구/군/시 이름을 입력하십시오 | 거주 지역 (예: Seoul) |

### 1-3. ⚠️ 키스토어와 비밀번호는 절대 잃어버리면 안 됩니다

- 이 `.jks` 파일과 비밀번호(스토어 비밀번호, 키 비밀번호)를 잃어버리면 **같은 앱의 업데이트를 낼 수 없습니다.** Google Play는 새 서명 키로 만든 AAB를 기존 앱의 업데이트로 인식하지 않습니다.
- 반드시 **비밀번호 관리자**나 **외장 백업(USB, 클라우드 암호화 저장소)** 등 최소 2곳에 복사해 두세요. 프로젝트 폴더 안에만 두면 컴퓨터가 고장 났을 때 그대로 끝입니다.
- Google Play는 **Play App Signing**을 사용하기 때문에, 업로드 키를 완전히 분실해도 [계정 복구 절차](https://support.google.com/googleplay/android-developer/answer/9842756)를 통해 업로드 키를 재설정할 수는 있습니다. 다만 신원 확인 서류 제출 등 절차가 번거롭고 수일이 걸리므로, 애초에 분실하지 않는 것이 최선입니다.

## 2. key.properties 설정

1. `app\android\key.properties.example` 파일을 같은 폴더에 `key.properties`라는 이름으로 복사합니다.
2. 아래 값을 1장에서 만든 실제 정보로 채웁니다.

```properties
storePassword=키스토어_비밀번호
keyPassword=키_비밀번호
keyAlias=upload
storeFile=../upload-keystore.jks
```

`key.properties`와 `.jks` 파일은 `.gitignore`에 이미 등록되어 있어 git에 커밋되지 않습니다. 절대 직접 커밋하지 마세요.

## 3. 버전 확인 후 릴리즈 빌드

`app\pubspec.yaml`의 버전 줄을 확인하세요.

```yaml
version: 1.0.0+1
```

`1.0.0`이 사용자에게 보이는 버전명(versionName), `1`이 내부 빌드 번호(versionCode)입니다. 이후 업데이트할 때마다 `+` 뒤 숫자를 반드시 올려야 합니다(같은 번호로는 재업로드 불가).

빌드 명령:

```powershell
cd D:\Projects\leeeo-colorrush\app
flutter build appbundle --release
```

빌드가 끝나면 아래 경로에 AAB 파일이 생성됩니다.

```
D:\Projects\leeeo-colorrush\app\build\app\outputs\bundle\release\app-release.aab
```

이 파일이 Play Console에 업로드할 결과물입니다.

> 참고: 이 프로젝트에는 `v*` 태그를 push하면 `.github\workflows\android-release.yml`이 자동으로 서명된 AAB를 빌드해주는 CI가 이미 구성되어 있습니다. 로컬 빌드가 번거로우면 CI 활용법은 09번 문서(CI/CD 자동화)를 참고하세요. 다만 **첫 출시는 이 문서의 절차대로 수동으로 한 번 완료하는 것을 권장**합니다.

## 4. Play Console 개발자 계정 만들기

1. https://play.google.com/console 접속 후 계정 유형(개인/조직)을 선택합니다. 개인 개발자로 충분합니다.
2. **1회성 등록비 $25**를 카드로 결제합니다.
3. 개인 신원 확인 절차가 진행됩니다. 실명, 주소, 전화번호, 정부 발급 신분증 등을 요구할 수 있으며 완료까지 수 시간~2일 정도 걸릴 수 있습니다.
4. 계정이 승인되면 콘솔 대시보드에 진입할 수 있습니다.

## 5. 앱 만들기 및 설정 마법사

**Play Console > 앱 만들기**에서 앱 이름(`Color Rush` / `컬러 러시`), 기본 언어(한국어), 앱/게임 여부(게임), 무료/유료(무료)를 선택하고 생성합니다.

앱을 만들면 아래 항목들을 순서대로 채우라는 안내가 뜹니다(**정책 > 앱 콘텐츠** 메뉴에 모두 모여 있습니다).

### 5-1. 앱 액세스 권한

로그인이나 특정 권한 없이 전체 기능을 사용할 수 있으므로 **전체 공개(제한 없음)** 로 설정합니다.

### 5-2. 광고

앱에 광고가 포함되어 있으므로 **예, 광고가 포함되어 있습니다**를 선택합니다.

### 5-3. 콘텐츠 등급 설문

**Play Console > 정책 > 앱 콘텐츠 > 콘텐츠 등급**에서 설문에 답합니다. Color Rush는 스트룹 반응 퍼즐/캐주얼 게임이며 폭력, 도박, 성인 콘텐츠, 사용자 생성 콘텐츠가 전혀 없으므로 관련 질문에 모두 "아니요"로 답하면 됩니다. 예상 결과는 **전체이용가** 등급입니다.

### 5-4. 타겟 대상 및 콘텐츠

**타겟 연령층**을 선택할 때 **13세 이상**을 선택하는 것을 권장합니다.

> ⚠️ 아동(13세 미만)을 타겟으로 선택하면 **Google Play 아동 정책** 및 **미국 COPPA** 등 아동 개인정보보호 규정이 적용되어, 개인 맞춤 광고를 포함한 여러 기능에 강한 제약이 걸립니다. Color Rush는 아동 대상 앱이 아니므로 13세 이상으로 설정하세요.

### 5-5. 뉴스 앱 여부

뉴스 앱이 아니므로 **아니요**를 선택합니다.

### 5-6. 데이터 보안 양식

**Play Console > 정책 > 앱 콘텐츠 > 데이터 보안**에서 작성합니다. Color Rush는 로그인/서버가 없지만 **AdMob SDK가 광고 ID 등을 수집**하므로 아래처럼 답해야 합니다(2026년 초 기준 확인된 내용이며, 실제 화면의 세부 문구는 콘솔 업데이트에 따라 달라질 수 있습니다).

| 질문 | 답변 |
| --- | --- |
| 앱에서 필수 사용자 데이터 유형을 수집하거나 공유하나요? | **예** (AdMob을 쓰면 사실상 항상 "예"입니다) |
| 수집하는 모든 사용자 데이터를 암호화하여 전송하나요? | **예** (AdMob SDK는 TLS로 전송) |
| 사용자가 데이터 삭제를 요청할 수 있는 방법을 제공하나요? | 서버에 사용자 데이터를 저장하지 않으므로, 실제 앱 구조에 맞게 정직하게 답하세요. 삭제 요청 경로가 없다면 **아니요/해당 없음**으로 표시하고 개인정보처리방침에 그 사실을 명시하는 것이 안전합니다. |

**데이터 유형 섹션**에서는 최소한 아래를 체크하세요.

- **기기 또는 기타 ID**: 광고 ID(Advertising ID), App Set ID가 여기 해당합니다. AdMob을 쓰는 이상 필수로 선언해야 합니다.
  - 수집 여부: 예
  - 공유 여부: 예 (AdMob으로 공유됨)
  - 목적: **광고 또는 마케팅**
  - "이 데이터 수집은 필수입니다" 또는 "사용자가 수집 여부를 선택할 수 있습니다" 중, Android 13+에서는 사용자가 시스템 설정으로 광고 ID를 재설정/삭제할 수 있으므로 **"사용자가 데이터 수집 여부를 선택할 수 있습니다"** 를 선택하는 것이 정확합니다.
- 필요에 따라 **앱 활동**(광고 상호작용), **앱 정보 및 성능**(진단)도 AdMob 관련 항목으로 추가될 수 있습니다. 정확한 체크리스트는 [Google Play 데이터 보안 공식 가이드](https://support.google.com/googleplay/android-developer/answer/10787469)를 참고하며, 실제 SDK 동작과 다르게 선언하면 **정책 위반으로 앱이 내려갈 수 있으니** 보수적으로(수집하지 않는다고 거짓 선언하지 않도록) 작성하세요.

### 5-7. 개인정보처리방침 URL

08번 문서에서 배포한 URL을 입력합니다. 형식 예시:

```
https://아이디.github.io/저장소명/privacy.html
```

이 URL이 실제로 열리는지 브라우저에서 먼저 확인한 뒤 입력하세요. 빈 페이지나 404가 뜨면 심사에서 반려됩니다.

## 6. 스토어 등록정보

**Play Console > 스토어 설정 > 스토어 등록정보**

| 항목 | 글자 수 제한 | 예시 |
| --- | --- | --- |
| 제목 | 30자 | `컬러 러시 - 반응속도 게임` |
| 짧은 설명 | 80자 | `색깔과 글자가 다른 스트룹 효과 반응 게임! 순발력을 테스트해보세요.` |
| 전체 설명 | 4000자 | 아래 예시 참고 |

**전체 설명 예시(한국어)**:

```
컬러 러시(Color Rush)는 화면에 나타나는 글자의 "뜻"과 "색깔"이 다를 때
순간적으로 올바른 답을 골라야 하는 스트룹 효과 기반 반응속도 게임입니다.

- 간단한 규칙, 짧은 세션: 언제 어디서나 즐길 수 있습니다.
- 순발력과 집중력을 동시에 훈련합니다.
- 로그인 없이 바로 플레이할 수 있습니다.
- 인앱 구매로 광고를 제거하고 방해 없이 즐길 수 있습니다.

지금 다운로드하고 나의 반응속도를 시험해보세요!
```

**그래픽 자산 규격** (2026년 기준, 변동될 수 있으니 [공식 문서](https://support.google.com/googleplay/answer/9866151)로 최종 확인 권장):

- 앱 아이콘: 512×512px PNG
- 피처 그래픽: 1024×500px PNG/JPG (알파 채널 없이)
- 스크린샷: 휴대전화용 최소 2장 이상, 각 변 320px~3840px, 가로세로 비율 16:9~9:16

## 7. 내부 테스트 → 프로덕션 승격

### 7-1. 내부 테스트 트랙

**Play Console > 테스트 및 출시 > 테스트 > 내부 테스트 > 새 출시 버전 만들기**

1. 3장에서 만든 `app-release.aab` 파일을 업로드합니다.
2. 출시 노트를 간단히 작성하고 저장/게시합니다.
3. 테스터 탭에서 이메일 목록을 만들어 본인 계정(또는 지인 계정)을 등록합니다.
4. 테스터에게 전달되는 참가 링크를 통해 실제 기기에 설치해보고, 광고/인앱결제/게임 플레이가 정상 동작하는지 확인합니다.

### 7-2. ⚠️ 신규 개인 개발자 계정의 비공개 테스트 요건

2023년 11월 13일 이후 새로 만든 **개인** Play 개발자 계정은 **프로덕션에 바로 출시할 수 없습니다.** 아래 조건을 먼저 충족해야 합니다(2026년 기준 요건이며, 향후 변경될 수 있습니다).

- **최소 12명의 테스터**가 **비공개 테스트**에 참여(opt-in) 상태를 유지해야 합니다.
- 이 상태를 **최근 14일 동안 연속으로 유지**해야 프로덕션 액세스 신청 버튼이 활성화됩니다.
- 설치 수가 아니라 "테스트 참여 opt-in 상태"가 기준이므로, 12명을 딱 맞추기보다 15명 이상 여유 있게 확보하는 것이 안전합니다.
- 이 요건은 개인 계정에만 적용되며, **조직(사업자) 계정은 즉시 프로덕션 출시가 가능**합니다.

**Play Console > 테스트 및 출시 > 테스트 > 비공개 테스트**에서 트랙을 만들고 테스터 이메일을 등록해 진행하세요. 14일 요건을 충족하면 "프로덕션 액세스 신청" 버튼이 나타납니다.

> ⚠️ 이 정책은 계속 바뀌어 왔습니다(20명→12명 등). 반드시 [Play Console 공식 고객센터 - 새로운 개인 개발자 계정의 앱 테스트 요구사항](https://support.google.com/googleplay/android-developer/answer/14151465)에서 최신 인원수·기간을 확인하세요.

### 7-3. 프로덕션 승격

내부/비공개 테스트에서 문제가 없다면 **Play Console > 테스트 및 출시 > 프로덕션 > 새 출시 버전 만들기**에서 같은 AAB(또는 새 빌드)를 프로덕션 트랙에 올리고 심사를 제출합니다.

---

## 8. 심사 기간과 리젝 대응

- 첫 프로덕션 심사는 보통 **수 시간~7일** 정도 소요됩니다. 신규 계정이거나 정책 검토가 필요한 경우 더 걸릴 수 있습니다.
- 리젝(정책 위반) 통보를 받으면 **Play Console > 정책 > 앱 콘텐츠** 또는 알림 메시지에 구체적인 사유가 나옵니다. 데이터 보안 선언 불일치, 개인정보처리방침 URL 접근 불가, 콘텐츠 등급 오답 등이 흔한 사유입니다.
- 문제를 수정한 뒤에는 새 버전을 다시 올리거나, 동일 버전에서 콘텐츠(스토어 등록정보 등)만 수정 후 **재검토 요청**을 보낼 수 있습니다.
