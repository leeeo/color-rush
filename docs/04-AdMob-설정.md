# 04. AdMob 설정

> 문서 목적: AdMob 계정과 광고 단위를 만들고, 발급받은 ID를 Color Rush 코드의 정확한 위치에 넣어 실제 광고 수익이 나오게 만듭니다.

## ✅ 선행 조건

- [ ] Google 계정 (개인 Gmail 계정이면 충분합니다)
- [ ] 앱 패키지명 확인: Android `com.leeeo.colorrush`, iOS도 동일 번들 ID 예정
- [ ] 이 문서는 **가장 먼저 진행**해도 됩니다. 06(안드로이드 출시), 07(iOS 출시) 문서보다 먼저 끝내 두면 스토어 등록 정보 입력 시 광고 관련 항목(데이터 보안, App Privacy)을 바로 채울 수 있습니다.
- [ ] 스토어에 앱을 아직 등록하지 않아도 AdMob 앱은 미리 만들 수 있습니다 (아래 3장 참고).

## ⏱ 예상 소요 시간

- 실작업: 30~50분 (계정 생성 + 앱 2개 + 광고 단위 6개 + 코드 수정)
- 대기 시간(별도): GDPR 메시지 반영 즉시~수 시간, app-ads.txt 크롤링 최대 24시간, 첫 지급까지는 수익이 쌓이는 기간에 따라 수개월 소요될 수 있음

---

## 1. AdMob 계정 만들기

1. https://admob.google.com 접속 후 기존 Google 계정으로 로그인합니다.
2. 처음 방문하면 가입 마법사가 뜹니다. **국가/지역**을 실제 거주 국가(대한민국)로 정확히 선택하세요. 나중에 변경하기 까다롭습니다.
3. "애드센스 계정과 연결하시겠습니까?" 같은 안내가 나올 수 있습니다. 기존 애드센스 계정이 없다면 AdMob이 자동으로 애드센스 계정을 함께 만들어 줍니다(수익 지급은 이 애드센스 쪽 지급 시스템을 그대로 씁니다). 기존 애드센스 계정이 있다면 연결해도 되고, 새로 만들어도 됩니다.
4. **결제(세금/지급) 정보는 지금 입력하지 않아도 됩니다.** 계정 생성 자체는 결제 정보 없이 가능하며, 수익이 발생하기 전에만 채워 넣으면 됩니다. 다만 결제 정보를 넣지 않으면 광고 게재 자격 검토 자체가 진행되지 않으니, 앱을 실제로 출시할 즈음에는 반드시 입력하세요 (AdMob 콘솔 좌측 **지급** 메뉴).

## 2. 앱 2개 등록 (Android / iOS)

AdMob은 스토어에 아직 올라가지 않은 앱도 먼저 등록해서 테스트할 수 있습니다.

**AdMob 콘솔 > 앱 > 앱 추가** 메뉴로 이동해 아래 과정을 Android용, iOS용 각각 한 번씩(총 2번) 진행하세요.

1. "이 앱이 앱 스토어에 게시되어 있나요?" 질문에서 **게시 취소됨(아직 스토어에 없음)** 을 선택합니다.
   - Color Rush를 아직 Play 스토어/App Store에 올리기 전이라면 이 옵션이 맞습니다.
   - 06/07번 문서를 따라 실제로 스토어에 출시한 뒤에는, AdMob 콘솔의 해당 앱 설정에서 **스토어에 연결**하여 "게시됨" 상태로 전환해야 합니다. 이 연결을 해야 앱 준비 상태 검토가 진행되고 광고가 정상적으로 게재됩니다.
2. 플랫폼(Android / iOS)을 선택하고 앱 이름에 `Color Rush`를 입력합니다.
3. "사용자 측정항목을 사용 설정하시겠습니까?"(Firebase 연동)는 선택 사항입니다. 이 프로젝트는 Firebase를 쓰지 않으므로 건너뛰어도 무방합니다.
4. 앱을 만들면 **앱 ID**가 발급됩니다. 형식은 `ca-app-pub-1234567890123456~1234567890` 처럼 **물결표(~)** 를 포함합니다. 이 값을 메모해 두세요. Android용 앱 ID, iOS용 앱 ID 총 2개가 생깁니다.

같은 방식으로 iOS 앱도 하나 더 만드세요. 최종적으로 **앱 2개(Android 1개, iOS 1개), 앱 ID 2개**가 준비됩니다.

## 3. 광고 단위 6개 만들기

Color Rush 코드는 앱마다 **배너 1개, 전면(interstitial) 1개, 보상형(rewarded) 1개**를 사용합니다. Android 앱과 iOS 앱 각각 3개씩, 합쳐서 **총 6개**의 광고 단위를 만들어야 합니다.

**AdMob 콘솔 > 앱 > (Android 앱 선택) > 광고 단위 > 광고 단위 추가** 메뉴로 이동합니다.

각 앱마다 아래 3개를 생성하세요.

| 광고 단위 | 형식 | 권장 설정 |
| --- | --- | --- |
| 배너 | 배너 | 이름 예: `banner_main`. 크기는 앱이 자동으로 처리하므로 콘솔에서 특별히 손댈 항목은 없습니다. |
| 전면 | 전면 | 이름 예: `interstitial_gameover`. 게임오버 화면 전환 시 노출됩니다(코드에 60초 쿨다운 + 3판마다 1회 로직이 이미 구현되어 있습니다). |
| 보상형 | 보상형 | 이름 예: `rewarded_bonus`. 보상 유형/금액은 콘솔 기본값 그대로 두어도 코드 동작에 영향 없습니다(코드는 시청 완료 콜백만 사용). |

생성하면 각각 `ca-app-pub-1234567890123456/1234567890` 형식의 **광고 단위 ID**(마지막 구분자가 **슬래시 /**)가 발급됩니다.

Android에서 3개, iOS에서 3개를 만들면 **총 6개의 광고 단위 ID**가 나옵니다. 표를 만들어 정리해 두는 것을 권장합니다.

| 앱 | 광고 단위 | ID |
| --- | --- | --- |
| Android | 배너 | ca-app-pub-...../.... |
| Android | 전면 | ca-app-pub-...../.... |
| Android | 보상형 | ca-app-pub-...../.... |
| iOS | 배너 | ca-app-pub-...../.... |
| iOS | 전면 | ca-app-pub-...../.... |
| iOS | 보상형 | ca-app-pub-...../.... |

> ⚠️ **앱 ID(~ 포함)와 광고 단위 ID(/ 포함)는 완전히 다른 값입니다.** 형식이 비슷해 보여서 헷갈리기 쉽지만, 넣는 위치도 다르고 하나라도 잘못 넣으면 광고가 아예 안 뜨거나 계정 정책 위반으로 이어질 수 있습니다. 앱 ID는 "이 앱이 AdMob의 어떤 앱인지"를 식별하는 값이고, 광고 단위 ID는 "이 화면의 이 광고 자리가 어떤 광고 단위인지"를 식별하는 값입니다.

## 4. 코드에 ID 넣기

### (a) 앱 ID (~ 포함): 플랫폼 설정 파일에 삽입

**Android**: `app\android\app\src\main\AndroidManifest.xml`

```xml
<meta-data
    android:name="com.google.android.gms.ads.APPLICATION_ID"
    android:value="ca-app-pub-여기에_Android_앱_ID~여기"/>
```

현재 이 자리에는 Google 공식 **테스트 앱 ID**(`ca-app-pub-3940256099942544~3347511713`)가 들어 있습니다. 파일 안 주석에 정확한 위치가 표시되어 있으니 그 값을 실제 Android 앱 ID로 교체하세요.

**iOS**: `app\ios\Runner\Info.plist`

```xml
<key>GADApplicationIdentifier</key>
<string>ca-app-pub-여기에_iOS_앱_ID~여기</string>
```

역시 테스트 앱 ID(`ca-app-pub-3940256099942544~1458002511`)가 들어 있는 자리이며, 주석으로 위치가 안내되어 있습니다. iOS 앱 ID로 교체하세요.

### (b) 광고 단위 ID (/ 포함): `ad_config.dart`에 삽입

`app\lib\monetization\ad_config.dart` 파일을 여세요. 파일 상단 주석에 교체 방법이 자세히 설명되어 있습니다. `_real...`로 시작하는 상수 6개를 찾아서 발급받은 광고 단위 ID로 교체하면 됩니다.

```dart
static const String _realBannerAndroid = 'ca-app-pub-XXXXXXXXXXXXXXXX/XXXXXXXXXX'; // ← Android 배너 ID로 교체
static const String _realBannerIos = 'ca-app-pub-XXXXXXXXXXXXXXXX/XXXXXXXXXX';      // ← iOS 배너 ID로 교체
static const String _realInterstitialAndroid = ...;  // ← Android 전면 ID로 교체
static const String _realInterstitialIos = ...;      // ← iOS 전면 ID로 교체
static const String _realRewardedAndroid = ...;      // ← Android 보상형 ID로 교체
static const String _realRewardedIos = ...;          // ← iOS 보상형 ID로 교체
```

`_test...`로 시작하는 6개(Google 공식 테스트 ID)는 **절대 수정하지 마세요.** 디버그 빌드에서 계속 이 값을 사용합니다.

## 5. 코드의 안전장치 (왜 이렇게 만들었는지)

`ad_config.dart`에는 실수로 인한 사고를 막는 안전장치가 들어 있습니다.

- **디버그 빌드는 항상 테스트 광고를 강제로 사용합니다** (`kDebugMode` 체크). 개발 중에 실제 광고가 뜨는 일이 없습니다.
- **`_real...` 값이 아직 placeholder(`XXXX` 포함)라면, 릴리즈 빌드에서도 테스트 광고로 자동 폴백합니다.** 즉 6개 ID 중 하나라도 교체를 깜빡하면, 그 광고 슬롯은 스토어에 배포된 후에도 계속 테스트 광고만 보여주고 **수익이 0원**입니다. 앱을 출시하기 전 6개 상수를 전부 교체했는지 반드시 다시 확인하세요.

## 6. ⚠️ 절대 하지 말아야 할 것: 자기 광고 클릭

- 본인의 실제 광고를 클릭하거나, 본인 기기에서 반복적으로 광고를 노출/클릭하는 행위는 **무효 트래픽(invalid traffic)** 으로 간주되어 **AdMob 계정이 영구 정지**될 수 있습니다. 계정이 한 번 정지되면 사실상 복구가 매우 어렵고, 새 계정을 만들어도 연결된 정보 때문에 다시 정지되는 경우가 많습니다.
- 테스트할 때는 반드시 위 5장에서 설명한 **테스트 광고**(디버그 빌드, 또는 placeholder 상태의 릴리즈 빌드)로만 확인하세요. 실제 광고 단위 ID가 들어간 빌드로는 절대 직접 광고를 눌러보지 마세요.
- 지인에게 "광고 좀 눌러 달라"고 부탁하는 것도 동일하게 정책 위반입니다.

## 7. GDPR 동의 메시지 (UMP) 게시하기

Color Rush 앱에는 이미 **Google UMP(User Messaging Platform) 동의 플로우**가 코드에 구현되어 있습니다. 하지만 UMP SDK가 화면에 표시할 동의 메시지 자체는 AdMob 콘솔에서 별도로 만들어 **게시(Publish)** 해야 합니다. 이 게시 작업을 하지 않으면 SDK가 보여줄 메시지가 없어서, 유럽(EEA)·영국·스위스 사용자에게는 개인 맞춤 광고가 제대로 나오지 않을 수 있습니다.

1. **AdMob 콘솔 > 개인정보보호 및 메시지** 메뉴로 이동합니다.
2. **유럽 규정에 따른 메시지(GDPR)** 카드에서 메시지 만들기를 시작합니다.
3. 앱을 선택하고(Android/iOS 둘 다 포함), 동의 화면 문구/버튼 스타일을 설정합니다. 기본 템플릿을 그대로 써도 무방합니다.
4. 마지막 단계에서 반드시 **게시(Publish)** 버튼을 눌러야 실제로 적용됩니다. 초안 저장만으로는 동작하지 않습니다.

> ⚠️ EEA 외 지역에서는 이 메시지가 자동으로 표시되지 않습니다. UMP SDK가 사용자의 지역을 감지해서 필요한 경우에만 동의 화면을 띄우므로, 코드는 모든 지역에 동일하게 두면 됩니다. 다만 콘솔에서 메시지를 "게시"하지 않으면 EEA 사용자에게 아무것도 표시되지 않아 개인 맞춤 광고 게재에 제약이 생깁니다.

## 8. app-ads.txt 등록

`app-ads.txt`는 "이 앱의 광고 인벤토리를 판매할 권한이 있는 광고 네트워크 목록"을 개발자 웹사이트 루트에 공개하는 표준 텍스트 파일입니다. 이걸 등록해 두지 않으면 광고 단가가 낮아지거나(무효 인벤토리로 의심받아 입찰이 줄어듦), 2025년 1월 이후 생성된 앱은 광고 게재 자체가 제한될 수 있습니다.

1. **AdMob 콘솔 > 앱 > 모든 앱 > app-ads.txt** 메뉴에서 "app-ads.txt 설정 방법"을 클릭하면, 본인 계정 전용 코드 한 줄을 복사할 수 있습니다. 예시 형식:
   ```
   google.com, pub-0000000000000000, DIRECT, f08c47fec0942fa0
   ```
2. 이 한 줄을 **웹사이트 루트**의 `website\app-ads.txt` 파일로 만들어 배포합니다. (이 프로젝트의 웹사이트는 `website/` 폴더에 있고, GitHub Pages 배포는 08번 문서에서 다룹니다. 08번 문서를 먼저 마치고 사이트가 실제로 `https://도메인/app-ads.txt` 경로에서 열리는지 확인한 뒤 이 단계를 진행하세요.)
3. 스토어 등록정보의 **개발자 웹사이트** 항목에 반드시 위 파일이 배포된 도메인을 입력해야 합니다.
   - Google Play: **Play Console > 앱 설정 > 스토어 등록정보 > 연락처 세부정보 > 웹사이트**
   - App Store: 앱 정보의 **마케팅 URL**(또는 지원 URL)
4. 등록 후 AdMob이 크롤링하여 확인하기까지 **최대 24시간** 정도 걸립니다. AdMob 콘솔의 app-ads.txt 상태가 "확인됨"으로 바뀌면 완료입니다.

> ⚠️ 주의: 반드시 도메인 **루트**(`https://도메인/app-ads.txt`)에 있어야 인식됩니다. 하위 폴더(`.../blog/app-ads.txt`)에 두면 크롤러가 찾지 못합니다. 스토어에 등록한 웹사이트 URL과 실제 파일이 서빙되는 도메인이 정확히 일치해야 합니다.

## 9. 수익 지급 기준

- **지급 기준액은 보고 통화가 USD일 때 $100** 입니다(국가·통화별로 다를 수 있으니 정확한 표는 [공식 문서](https://support.google.com/admob/answer/2772208)를 확인하세요). $100 미만이면 지급되지 않고 다음 달로 이월됩니다.
- 수익이 **인증 기준액**(보통 $10)에 도달하면 본인 확인과 **주소 확인(PIN)** 절차가 시작됩니다. 등록한 실제 주소로 6자리 PIN이 담긴 우편물이 발송되며, 도착까지 보통 2~4주(최대 4개월)가 걸립니다. **AdMob 콘솔 > 지급 > 인증**에서 PIN을 입력하면 지급 보류가 해제됩니다.
- PIN 입력은 3회까지만 시도할 수 있고, 모두 실패하면 계정이 잠길 수 있으니 정확히 입력하세요. 오래 기다려도 우편이 오지 않으면 콘솔에서 재발송을 요청할 수 있습니다(최대 3회).
- 결제 수단(은행 계좌 등)과 세금 정보도 지급 전에 등록해야 합니다. **AdMob 콘솔 > 지급** 메뉴에서 진행하세요.
- ⚠️ 위 금액·기간은 정책에 따라 변동될 수 있습니다. 최신 정보는 [Google AdMob 고객센터 - 지급 기준액](https://support.google.com/admob/answer/2772208)에서 확인하세요.
