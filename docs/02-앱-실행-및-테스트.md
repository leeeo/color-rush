# 02. 앱 실행 및 테스트

**문서 목적**: Color Rush 앱을 내 컴퓨터에서 직접 실행하고, 자동 테스트를 돌리고, 릴리즈용 APK까지 빌드해봅니다.

✅ **선행 조건**
- [ ] [01-개발환경-설정.md](01-개발환경-설정.md) 완료 (`flutter doctor` 정상)
- [ ] (실기기로 테스트하려면) 휴대폰 USB 디버깅 연결 완료

⏱ **예상 소요 시간**: 10~20분 (첫 빌드는 더 걸릴 수 있음)

---

이 문서의 모든 명령어는 **앱 폴더 안에서** 실행합니다. PowerShell을 열면 먼저 이동하세요.

```powershell
cd D:\Projects\leeeo-fable\app
```

이후 이 문서의 명령어는 전부 이 폴더 기준입니다.

## 1. 의존성 설치

```powershell
flutter pub get
```

`pubspec.yaml`에 적힌 패키지들(google_mobile_ads, in_app_purchase, shared_preferences 등)을 내려받습니다.

## 2. 정적 분석 (코드 검사)

```powershell
flutter analyze
```

문법 오류나 잠재적 버그를 미리 잡아줍니다. 현재 상태에서는 이슈 없이 깨끗하게 통과해야 합니다.

## 3. 자동 테스트 실행

```powershell
flutter test
```

이 프로젝트에는 자동 테스트 9개가 있습니다.

- `test/game_logic_test.dart`: 게임 규칙(라운드 생성, 난이도 곡선, 정답 판정) 검증 7개
- `test/widget_test.dart`: 홈 화면 렌더링, 게임 진입, 게임 방법 다이얼로그 등 화면 동작 검증 2개

모두 통과(`All tests passed!`)해야 정상입니다.

## 4. 기기에서 실행하기 (기기가 연결되어 있을 때)

```powershell
flutter run
```

연결된 기기가 여러 개면 선택하라는 메시지가 뜹니다. 기기가 하나만 연결되어 있으면 바로 그 기기에 설치되고 실행됩니다.

## 5. 웹 브라우저로 빠르게 확인하기 (기기 없이)

기기가 아직 없거나, 게임 로직만 빠르게 확인하고 싶을 때는 Chrome으로 바로 실행할 수 있습니다.

```powershell
flutter run -d chrome
```

**중요**: 웹 실행에서는 광고(배너/전면/보상형)가 뜨지 않습니다. **이것은 버그가 아니라 정상 동작**입니다. AdMob과 인앱 결제는 모바일(Android/iOS) 전용이라 웹 빌드에서는 아예 초기화되지 않습니다. 게임 자체의 동작(라운드 생성, 점수, 난이도 상승)만 빠르게 확인하고 싶을 때 웹 실행을 활용하세요.

## 6. 릴리즈용 APK 빌드하기

```powershell
flutter build apk --release
```

빌드가 끝나면 아래 경로에 APK 파일이 생성됩니다.

```
app\build\app\outputs\flutter-apk\app-release.apk
```

이 APK를 실기기에 직접 설치해서 테스트하려면, 기기를 USB로 연결한 상태에서 다음을 실행합니다.

```powershell
flutter install
```

또는 탐색기에서 위 경로의 `app-release.apk` 파일을 휴대폰으로 직접 전송한 뒤, 휴대폰에서 파일을 탭해 설치할 수도 있습니다(이 경우 "출처를 알 수 없는 앱 설치 허용"을 잠깐 켜야 할 수 있습니다).

## 7. 광고에 대한 중요 경고

- **디버그 빌드(`flutter run`)와 개발 중 빌드에서는 항상 Google 공식 테스트 광고**가 나옵니다. 실제 광고가 아니므로 수익이 발생하지 않으며, 마음껏 눌러봐도 괜찮습니다.
- 실제 광고 ID로 교체한 뒤(04번 문서 참고)에는 절대로 **본인이 직접 실제 광고를 반복해서 클릭하면 안 됩니다.** 무효 트래픽(자기 클릭)으로 감지되면 AdMob 계정이 정지될 수 있고, 한 번 정지되면 복구가 매우 어렵습니다. 테스트가 필요하면 항상 테스트 광고 ID나 테스트 기기 등록 기능을 사용하세요.
