# 01. 개발 환경 설정

**문서 목적**: 이 컴퓨터에서 Flutter 앱을 빌드하고 실행할 수 있도록 개발 환경을 확인하고, 부족한 부분(Android SDK)을 설치합니다.

✅ **선행 조건**
- [ ] [00-시작하기.md](00-시작하기.md) 를 읽었음
- [ ] PowerShell을 관리자 권한이 아니어도 좋으니 실행할 수 있음
- [ ] 인터넷 연결 (SDK 다운로드에 수백MB 필요)

⏱ **예상 소요 시간**: 15~40분 (인터넷 속도에 따라 SDK 다운로드 시간 차이 큼)

---

## 1. 이미 설치되어 있는 것

이 프로젝트를 준비하면서 아래 도구들은 이미 설치되어 있습니다.

- **Flutter 3.41.6** (scoop으로 설치됨)
- **Git**
- **Python 3.14**

정말로 설치되어 있는지 PowerShell에서 직접 확인해봅니다.

```powershell
flutter --version
git --version
python --version
```

`flutter --version` 을 실행하면 `Flutter 3.41.6` 이라는 줄과 함께 Dart SDK 버전 등이 출력되면 정상입니다. 만약 "flutter는 인식할 수 없는 명령어" 라는 오류가 나오면, scoop shim 경로가 PATH에 없는 상태이니 터미널을 새로 열어보거나 `scoop which flutter` 로 설치 위치를 확인하세요.

## 2. 아직 없는 것: Android SDK

Flutter 자체는 설치되어 있어도, Android용 앱을 빌드하려면 **Android SDK**와 **JDK(자바 개발 도구)**가 따로 필요합니다. Android Studio 전체를 설치하지 않고, 이 프로젝트에 포함된 스크립트로 필요한 부분만 자동 설치할 수 있습니다.

프로젝트 루트(`D:\Projects\leeeo-colorrush`)에서 PowerShell을 열고 다음을 실행하세요.

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup-android.ps1
```

이 스크립트가 자동으로 처리하는 일:

1. Temurin JDK 17 설치 (scoop 우선 시도, 실패하면 winget으로 폴백)
2. `JAVA_HOME` 환경 변수 설정
3. Android SDK cmdline-tools 최신 버전을 자동으로 찾아 다운로드
4. 필수 SDK 패키지 설치: `platform-tools`, `platforms;android-35`, `platforms;android-36`, `build-tools;35.0.0`, `build-tools;36.0.0`
5. SDK 라이선스 전체 자동 동의
6. `ANDROID_HOME` 환경 변수 설정
7. `flutter config --android-sdk` 로 Flutter에 SDK 경로 알려주기
8. 마지막에 `flutter doctor -v` 로 결과를 보여줌

이 스크립트는 **여러 번 실행해도 안전**합니다(멱등성). 이미 설치된 구성 요소는 자동으로 건너뜁니다. 중간에 실패했거나 나중에 SDK 버전을 더 추가하고 싶을 때도 그냥 다시 실행하면 됩니다.

> Android SDK cmdline-tools 다운로드는 약 150MB이고, 이후 SDK 패키지들까지 합치면 수백MB가 추가로 받아집니다. 네트워크 환경에 따라 10~30분 정도 걸릴 수 있습니다.

## 3. 설치 결과 확인

스크립트 실행이 끝나면 **새 PowerShell 창을 하나 더 열어서**(환경 변수가 새 세션부터 적용되므로) 아래 명령으로 최종 확인합니다.

```powershell
flutter doctor -v
```

다음 항목들 앞에 초록색 체크(✓)가 있으면 정상입니다.

- Flutter (Channel stable, 3.41.6)
- Android toolchain
- (실기기를 연결했다면) Connected device

`flutter doctor` 오류가 남아 있다면 [11-문제해결-FAQ.md](11-문제해결-FAQ.md) 를 참고하세요.

## 4. 실기기(휴대폰)로 테스트하고 싶다면: USB 디버깅 연결

에뮬레이터 없이 실제 Android 휴대폰으로 바로 테스트하는 것이 가장 빠르고 확실합니다.

1. 휴대폰의 **설정 > 휴대전화 정보**로 들어가서 **빌드 번호**를 5~7번 연속으로 탭합니다. "개발자 모드가 활성화되었습니다" 라는 메시지가 뜨면 성공입니다.
2. **설정 > 시스템 (또는 추가 설정) > 개발자 옵션**으로 들어갑니다.
3. **USB 디버깅**을 켭니다.
4. 휴대폰을 USB 케이블로 컴퓨터에 연결합니다.
5. 휴대폰 화면에 "USB 디버깅을 허용하시겠습니까?" 팝업이 뜨면 **허용**을 누릅니다(이 컴퓨터에서 항상 허용 체크박스도 눌러두면 다음부터 안 물어봅니다).
6. PowerShell에서 인식 여부를 확인합니다.

```powershell
flutter devices
```

연결한 기기의 이름이 목록에 나타나면 준비 완료입니다.

## 5. 에뮬레이터는 선택 사항입니다

Android Studio의 에뮬레이터(가상 기기)를 쓸 수도 있지만, 이 프로젝트에서는 **필수가 아닙니다**. 실제 기기가 있다면 실기기 연결이 더 빠르고 실제 성능/광고 표시를 확인하기에도 정확합니다. 에뮬레이터를 쓰고 싶다면 Android Studio를 설치하고 AVD Manager로 가상 기기를 만들면 되지만, 이 문서 세트에서는 다루지 않습니다.
