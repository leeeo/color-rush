# 08. 웹사이트 배포

**문서 목적**: `website/` 폴더에 있는 정적 마케팅 웹사이트를 GitHub Pages로 배포하고, 배포 전에 반드시 채워야 할 항목들을 확인합니다.

✅ **선행 조건**
- [ ] GitHub 계정 (무료, https://github.com/signup)
- [ ] Git 사용법 기본 (`git add`, `git commit`, `git push`)
- [ ] 이 프로젝트가 로컬 git 저장소로 초기화되어 있음 (완료됨, 원격 저장소만 추가하면 됨)

⏱ **예상 소요 시간**: 20~30분

---

★ **중요: 이 문서는 스토어 심사 제출 전에 먼저 끝내야 합니다.** Google Play Console과 Apple App Store Connect는 앱 심사를 제출할 때 개인정보처리방침(Privacy Policy) URL을 **필수로** 요구합니다. 그 URL은 웹사이트를 배포해야만 생깁니다. 따라서 순서는 반드시 "웹사이트 배포 → 스토어 심사 제출" 이어야 합니다.

## 1. website/ 폴더 구성

| 파일 | 용도 |
|---|---|
| `index.html` | 랜딩 페이지 (게임 소개, 다운로드 버튼) |
| `privacy.html` | 개인정보처리방침 |
| `terms.html` | 이용약관 |
| `support.html` | 지원 / 문의 페이지 |
| `style.css` | 전체 페이지 공통 스타일 |
| `robots.txt`, `sitemap.xml` | 검색엔진 크롤링 설정 |
| `404.html` | 존재하지 않는 페이지 접근 시 표시 |

전부 정적 HTML/CSS라서 별도 서버나 빌드 과정 없이 파일 그대로 배포할 수 있습니다.

## 2. 로컬에서 미리보기

가장 간단한 방법은 파일 탐색기에서 `website\index.html` 을 더블클릭해서 브라우저로 여는 것입니다.

내부 링크 이동이나 상대 경로를 실제 서버 환경과 똑같이 테스트하고 싶다면, 프로젝트에 이미 있는 Python으로 간이 서버를 띄울 수 있습니다.

```powershell
cd D:\Projects\leeeo-colorrush\website
python -m http.server
```

이후 브라우저에서 `http://localhost:8000` 으로 접속하면 됩니다. 종료하려면 PowerShell 창에서 `Ctrl + C`를 누르세요.

## 3. 배포 전 반드시 채워야 할 항목 (TODO 확인)

`website/` 안의 파일들에는 `<!-- TODO -->` 형태의 주석으로 아직 채워지지 않은 자리표시자가 남아 있습니다. 아래 명령으로 전부 찾아볼 수 있습니다.

```powershell
Select-String -Path D:\Projects\leeeo-colorrush\website\* -Pattern "TODO"
```

채워야 할 항목은 크게 다음과 같습니다.

- **연락 이메일**: `privacy.html`, `terms.html`, `support.html` 안의 `[TODO: your-email@example.com]` 부분
- **개발자명/회사명**: `privacy.html`, `terms.html` 안의 `[개발자/회사명 - TODO]` 부분
- **스토어 링크**: `index.html`의 다운로드 버튼(App Store, Google Play) `href="#"` 부분을 실제 스토어 페이지 URL로 교체
- **도메인(canonical URL)**: `index.html`, `privacy.html`, `terms.html`, `support.html` 상단의 `<!-- TODO: 실제 배포 도메인으로 canonical URL 교체 -->` 및 `og:url` 부분, 그리고 `robots.txt`의 Sitemap 줄, `sitemap.xml`의 `<loc>` 값들. 배포 후 실제 주소(`https://아이디.github.io/저장소명/` 등)로 전부 교체합니다.
- **최종 수정일**: `privacy.html`, `terms.html`의 "최종 수정일 / Last updated" 부분

## 4. GitHub 저장소 만들고 push하기

1. https://github.com/new 에서 새 저장소를 만듭니다 (Public도 무방합니다. 소스 코드를 공개하고 싶지 않다면 Private로 만들어도 GitHub Pages는 동작합니다).
2. 로컬 프로젝트에 원격 저장소를 연결하고 push합니다.

```powershell
cd D:\Projects\leeeo-colorrush
git remote add origin https://github.com/아이디/저장소명.git
git add .
git commit -m "Initial commit"
git branch -M main
git push -u origin main
```

## 5. GitHub Pages 활성화

1. GitHub 저장소 페이지에서 **Settings > Pages**로 이동합니다.
2. **Source**를 **"GitHub Actions"**로 선택합니다 (브랜치 직접 선택 방식이 아닙니다).
3. 이 프로젝트에는 이미 `.github\workflows\website-deploy.yml` 워크플로가 준비되어 있어서, `website/` 폴더에 변경이 생겨 `main` 브랜치에 push되면 **자동으로** 빌드 없이 그대로 배포됩니다.
4. 저장소의 **Actions** 탭에서 "Deploy Website" 워크플로가 실행되고 초록색 체크로 끝나는지 확인합니다.

배포가 끝나면 사이트 주소는 다음 형식입니다.

```
https://아이디.github.io/저장소명/
```

**Settings > Pages** 페이지 상단에도 정확한 주소가 표시됩니다.

## 6. 커스텀 도메인 연결 (선택)

자체 도메인(예: `colorrush.com`)이 있다면 **Settings > Pages > Custom domain**에 입력하면 됩니다. 도메인 등록업체(가비아, Route 53 등)에서 해당 도메인의 DNS에 GitHub Pages를 가리키는 CNAME(또는 A 레코드)을 추가해야 합니다. 정확한 값은 GitHub Pages 공식 문서를 확인하세요: https://docs.github.com/pages/configuring-a-custom-domain-for-your-github-pages-site

## 7. 도메인이 정해지면 TODO들을 다시 정리

3단계에서 채운 URL들을 실제 GitHub Pages 주소(또는 커스텀 도메인)로 다시 한번 확인하고, 변경사항을 커밋 후 push하면 자동으로 재배포됩니다.
