# 12. 비공개 테스트의 광고 비활성 빌드

## 결정

비공개 테스트에서는 광고 없이 게임을 확인하고, 정식 출시에서는 광고를 다시 사용한다. 광고 SDK·UMP·인앱 결제 코드를 삭제하는 변경이 아니다.

`ADS_ENABLED`는 컴파일 시 정해지는 Dart 빌드 플래그이며 **기본값은 `true`**다. 설치 후 콘솔이나 설정 화면에서 바꾸는 원격 플래그가 아니다.

| 빌드 | 플래그 | 동작 |
|---|---|---|
| 비공개 테스트 | `--dart-define=ADS_ENABLED=false` | 광고·UMP 초기화와 광고 UI, 광고 제거 구매·복원 UI를 실행하거나 표시하지 않음 |
| 정식 출시 | 생략하거나 `--dart-define=ADS_ENABLED=true` | 기존 광고·동의·구매 흐름 사용 |

광고 없는 테스트 AAB를 프로덕션으로 그대로 승급하면 안 된다. 정식 출시에는 기본값 `true`로 **다시 빌드한 새 버전**을 사용한다.

## 검증

저장소의 `app` 폴더에서 실행한다.

```powershell
flutter analyze
flutter test --dart-define=ADS_ENABLED=true
flutter test --dart-define=ADS_ENABLED=false
```

두 모드 모두 홈·게임·게임 오버 흐름과 SafeArea를 확인한다. 비활성 모드는 배너 자리를 위한 빈 공간, 구매·복원 버튼, 광고를 봐야 하는 이어하기 안내가 없어야 하며 광고/동의 플랫폼 호출도 없어야 한다.

## 비공개 테스트 1.0.2(3)

기존 업로드 키와 gitignore된 `android/key.properties`를 사용한다. 비밀 원본과 실행 사본 관리 절차는 [06. 안드로이드 출시](06-안드로이드-출시.md)를 따른다. 키·비밀번호를 저장소에 넣지 않는다.

```powershell
flutter build appbundle --release --build-name=1.0.2 --build-number=3 --dart-define=ADS_ENABLED=false
```

산출물: `app/build/app/outputs/bundle/release/app-release.aab` (저장소 루트 기준).

- versionName `1.0.2`, versionCode `3`, 패키지 `com.leeeo.colorrush`와 기존 업로드 인증서를 확인한다.
- `1.0.1(2)`는 로컬 검증용으로만 만들었으며 Play에는 올리지 않는다.
- Play Console > 테스트 및 출시 > 비공개 테스트 > Alpha에 업로드한다.
- 한국어 출시 노트: **테스트 버전에서는 광고를 표시하지 않습니다**
- 업로드 이후 출시 검토와 게시 개요의 Google 검토 제출을 완료한다. 제출은 승인·테스터 제공 완료와 구분해서 기록한다.

SDK를 유지하므로 AAB 안의 광고 SDK 코드나 `AD_ID` 선언이 없어지는 빌드가 아니다. 플래그의 효과는 실제 초기화·광고 요청·UI 실행을 막는 것이다. SDK가 포함됐다는 사실과 광고를 실제 요청했다는 사실을 혼동하지 않는다.

## 정식 출시 전

1. 새 버전 번호를 올린다. Play에 올린 versionCode `3`을 재사용하지 않는다.
2. AdMob > 개인 정보 보호 및 메시지 > 유럽 규정에서 Color Rush 동의 메시지를 준비·게시하고 실제 UMP 동작을 검증한다. 현재 이 작업은 정식 출시 직전으로 미뤘다.
3. 광고 단위, 개인정보처리방침, 공개 개발자 정보, 광고·데이터 보안 신고를 정식 앱 동작과 대조한다. 테스트 플래그를 이유로 현재 Play 신고나 스토어 설명을 바꾸지 않는다.
4. 광고 제거 상품과 결제 기능의 출시 여부는 별도 결정이다. 이 플래그가 판매자 계정이나 상품을 만드는 것은 아니다.
5. 기본값으로 새 AAB를 빌드한다.

```powershell
flutter build appbundle --release
```

기본값은 `ADS_ENABLED=true`다. 명시하려면 `--dart-define=ADS_ENABLED=true`를 붙인다. 기존 `false` 빌드 산출물을 재사용하지 말고 새 AAB의 버전·해시·실제 광고/동의 동작을 확인한다.

AdMob 앱·광고 단위와 `app-ads.txt`는 보존한다. 테스터의 개인 이메일이나 발송 원장은 이 공개 저장소에 두지 않는다.
